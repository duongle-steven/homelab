    Step 12a-1: staging nodes Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Three NixOS VMs in WSL, installed by nixie from one node definition shared with production, joined into a three-server k3s cluster with kube-vip and rook-ceph, upgraded in place one node at a time, and measured; metal/ (Ansible) removed.

    Architecture: Upstream nixos's infra/_modules/metal flake (NixOS configuration, disko, profiles) and its Terragrunt unit infra/<env>/metal (hooks: nixie, lab cluster enroll, lab cluster kubeconfig) are ported and adapted to this repository's k3s choices. Staging's machines are libvirt VMs created by an OpenTofu unit infra/staging/vms on a libvirt NAT network whose DHCP gives fixed leases by MAC; nixie answers their PXE boot as a proxyDHCP. A new lab cluster upgrade rebuilds the nodes in place, one at a time.

    Tech Stack: NixOS 26.05 (k3s 1.37 from nixos-unstable's k3s_1_37), disko, nixie, nixos-anywhere, OpenTofu + Terragrunt, libvirt (provider dmacvicar/libvirt 0.9.9), Go (cli/, upstream's internal/cluster), rook-ceph.

    Spec: docs/superpowers/specs/2026-10-31-staging-design.md

    Global Constraints

    • One node definition for staging and production (infra/_modules/metal/flake); metal/, nix develop .#metal, make metal and make clean's PXE line are removed in this plan.
    • Installed by nixie (PXE), never by nixos-anywhere alone or a prebuilt image.
    • VMs: 3 × 3.5 GB (3584 MiB), 2 vCPUs, zram swap. If the core does not fit: drop apps → squeeze the core (OSD toward 900 MB) → 3.75 GB per VM with WSL at 12 GB → WSL 13 GB last. Three nodes always.
    • Staging never runs with the sandbox: make staging refuses while k3d-homelab-dev-server-0 runs, make dev refuses while a staging VM runs; both refuse when C: has less than 30 GB free.
    • Latest stable, pinned exactly: Gateway API v1.7.0 (sandbox's k3d too), kube-vip v1.3.1, libvirt provider 0.9.9, nixie by commit in flake.lock; k3s 1.37 (k3s_1_37, matching the sandbox's rancher/k3s:v1.37.1-k3s1).
    • This repository's k3s choices, not upstream's: ServiceLB on; kube-vip serves the API VIP and only Services of class kube-vip.io/kube-vip-class; audit policy and flags (15c); --secrets-encryption; control-plane metrics (etcd-expose-metrics, controller-manager/scheduler bind-address=0.0.0.0, kube-proxy metrics-bind-address); disable: traefik, local-storage, gateway-api-crd; disable-helm-controller.
    • infra/<env>/cluster/config.json keeps its format and gains init_host; machines live in infra/<env>/metal/hosts.json (mac_address, ip, disk). Production's MACs stay placeholders.
    • Changes to ~/nixos-config (outside the repo) are shown to the user and made only after their yes.
    • Never make dev/make staging from a worktree; never print tokens (the k3s join token goes over SFTP, as upstream).

    Review Focus

    • A VM that PXE-boots but whose MAC is not in hosts.json: nixie must ignore it, not install something — Task 3's test boots no foreign VM, so the review checks nixie's flags.
    • make staging with a node already installed: nothing reinstalls it (machine_id_hash / state), only the upgrade runs — Task 4's Step 3 and Task 5's Step 3.
    • An upgrade that leaves a node NotReady or Ceph unhealthy: lab cluster upgrade stops before the next node — Task 5's TestUpgradeStopsOnUnhealthy.
    • WSL memory: a run that would push WSL into swap thrash — Task 7 records free memory and swap per phase.
    • The VIP while its holder is down: the API answers through the VIP from another node — Task 6's TestStagingVIPMoves.

    Interfaces: - Produces: libvirt network homelab-staging (NAT, 192.168.122.0/24-style range of the builder's choice, DHCP with one fixed lease per hosts.json MAC, no PXE options: nixie adds them), domains <host> (3584 MiB, 2 vCPUs, boot order network then disk, a sparse qcow2 system disk ≥ 80 GB and the rook-data partition on it per disks.nix). infra/staging/cluster/config.json = production's format + init_host, staging's VIP and service_vips in the libvirt network, domain a *.nip.io name for the VIP. - infra/staging/metal/terragrunt.hcl = upstream's (hooks nixie, lab cluster enroll --environment staging, lab cluster kubeconfig --environment staging --output infra/staging/kubeconfig.yaml), depending on vms.

    • Step 1: One VM first. If nixie cannot answer PXE on the libvirt bridge, stop and bring the failure to the user before working around it (the install method is the user's decision).
    • Step 2: ssh admin@<ip> hostname → the host's name; ssh admin@<ip> systemctl is-active k3s → active.
    • Step 3: Three hosts in hosts.json; apply again → kubectl --kubeconfig infra/staging/kubeconfig.yaml get nodes lists three Ready control-plane nodes; a second apply reinstalls nothing (nixie's recorded machine_id_hash).
    • Step 4: Commit feat(staging): three libvirt VMs installed by nixie and joined into k3s.
