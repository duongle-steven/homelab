    14f-2: the cluster tests on Ginkgo — Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: the 84 cluster tests become Ginkgo specs in test/e2e, selected by labels, with a per-spec timeout from the spec's context, and terratest leaves the module.

    Architecture: test/e2e (package e2e, one entry TestE2E) holds one top-level Describe per old test, named after it without Test (Describe("SSOKiali", Label("sso", "kiali"), …)); labels sit only on that container, as string literals, from the fixed set in test/scopes.yaml's labels:. test/internal/kube replaces terratest with calls that take a context.Context. lab test scope reads the specs' labels from the source (go/ast), turns scopes.yaml's label filters into one main filter and one filter per alone spec, and evaluates them with Ginkgo's own types.ParseLabelFilter. just test e2e --env <env> runs go tool ginkgo and adds && <env> to every filter.

    Tech Stack: Go 1.26, Ginkgo v2.34.0, Gomega v1.44.0 (latest on 2026-11-08: check again when pinning), testify only in test/offline, chromedp.

    Spec: docs/superpowers/specs/2026-11-08-test-layout-design.md (step 2, "14f-2")

    Global Constraints

    • No spec asserts less than its test did, and no wait gets longer; a wait may become a spec timeout.
    • Every scope group, full, always, the alone runs and the recipes' filters (just testbed, testbed-power, testbed-scan, dev-scan, production) select exactly the old tests that ran under them today (Task 1's record), except the spec's two intended differences: no offline test (already true since 14f-1) and no TestTestbed* on the sandbox.
    • Labels: lower case, - between words, only the set below, only on top-level containers.
    • --fail-on-empty on every Ginkgo run; one process (no -p); alone specs are Serial.
    • Reports in test/reports/e2e/ (git-ignored); GitHub Actions uploads them.
    • go tool ginkgo (the tool directive in test/go.mod); no separate install.
    • Main checkout only for just dev and just testbed; ci-check with the sandbox and testbed down.
    • A sandbox or testbed step is a stop: the user starts it (they shut WSL down between sessions). So the groups are proven on the sandbox together in Task 13, one group's filter at a time in conversion order, not as each lands (the spec's wording): a conversion mistake costs a re-run of its group either way, since the test code runs from the checkout and the sandbox does not depend on it.

    Conversion rules (Tasks 3–10)

    • One old TestX → var _ = Describe("X", Label(…), func() { … }), Serial (and Ordered) on alone specs.
    • t.Run steps that build on each other → Ordered container, one It per step; independent subtests (tables) → one It per entry. A subtest's name becomes its It text.
    • Every It takes ctx SpecContext and has SpecTimeout(d): d is at least the longest single wait inside it plus 5 minutes and at least twice its duration in .superpowers/post-merge/test-layout-full.log (PASS TestX (Ns)), rounded up to 5 minutes; testbed specs without a measured duration take the first rule only.
    • Every wait takes the spec's context: kube.* (Task 2), exec.CommandContext, http.NewRequestWithContext, chromedp contexts derived from ctx, Eventually(ctx, f).WithTimeout(old timeout).WithPolling(old tick).
    • Assertions are Gomega (Expect(err).NotTo(HaveOccurred()), Eventually(...).Should(...) keeping the old message); e2e helpers drop t and call Expect themselves. test/internal helpers keep testing.TB (the offline tests use them), and e2e passes GinkgoTB().
    • Environment gates go (LocalOnly, *SandboxOnly, testbedOnly, skipUnlessSandbox, sandboxOnly and the inline ENV checks): the environment labels replace them. The only skips left: an optional app absent and not asked for (skipUnlessDeployed), and the testbed's two "not on its list" skips (CloudNativePG), which are the same kind. skipUnlessSandbox's wait for the identity stack becomes a BeforeEach in the SSO and Woodpecker containers.
    • Cleanups: t.Cleanup/defer that undo cluster changes → DeferCleanup(func(ctx SpecContext) …); t.TempDir() → GinkgoT().TempDir(); t.Parallel() dropped.
    • Paths through repo.Root(); never "..".

    Review Focus

    • A spec that passes having checked nothing: a gate turned label where the gate also waited (skipUnlessSandbox), a Skip left behind, an Eventually without .Should. Task 11's dry-run check and the code reading at each task.
    • A wait still blind to the spec's context (a exec.Command, http.Get, time.Sleep, chromedp.NewContext(context.Background())): each conversion task greps for them.
    • A main filter that selects nothing (a branch touching only Velero): lab must print "", not a filter that --fail-on-empty fails. Task 11's tests.
    • A label typed wrong in a spec or a filter (trivy-operater): known only through scopes.yaml; Task 11's just cli check and Task 11's check both fail.
    • An alone spec reached through a manual --tests filter (--tests 'node-restart || logs') must run alone, never in the main run. Task 11's tests.
