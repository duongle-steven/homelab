    k3d Sandbox and Istio Gateway Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: The sandbox runs on k3d and production on k3s defaults, Cilium leaves the repo, and Istio serves the Gateways istio-system/gateway and istio-system/public; make dev passes 72/72 from scratch.

    Architecture: metal/ creates a one-server k3d cluster (k3s v1.37.1, traefik off) with the Gateway API CRDs in k3s's auto-deploy manifests, plus a host-network socat container that forwards 127.0.0.1:80/443/22 to the k3d node (where ServiceLB serves the Gateway); production's Ansible k3s role drops its Cilium-specific flags and gets kube-vip v1.2.4 with a service load balancer for one class. A new wrapper chart system/istio-system (Istio base + istiod 1.31.1, two Gateways, the wildcard certificate, the redirect route, a sandbox-only CoreDNS rewrite) replaces system/gateway, and every route moves to the new Gateway names.

    Tech Stack: k3d 5.9.0, k3s v1.37.1+k3s1, Istio 1.31.1, Gateway API v1.6.3 (standard channel), kube-vip v1.2.4, Ansible, Helm wrapper charts, Argo CD, Go tests.

    Spec: docs/superpowers/specs/2026-10-14-k3d-istio-design.md

    Global Constraints

    • Versions, pinned exactly: k3d 5.9.0 (nixpkgs-unstable), rancher/k3s:v1.37.1-k3s1 / v1.37.1+k3s1, Istio charts base and istiod 1.31.1 from https://blob.istio.io/istio-release/charts, Gateway API v1.6.3 standard-install.yaml, ghcr.io/kube-vip/kube-vip:v1.2.4.
    • Gateway names: istio-system/gateway (LAN, listeners http 80, https 443, ssh 22) and istio-system/public (Tunnel, https only, Service ClusterIP); certificate secret wildcard-tls; generated Services gateway-istio and public-istio.
    • global.publicGateway: public in production, gateway in the sandbox.
    • Production kube-vip: API VIP 192.168.1.100 as before; service load balancer only for loadBalancerClass: kube-vip.io/kube-vip-class; Gateway gateway on 192.168.1.224, wireguard on 192.168.1.225.
    • The sandbox has no kube-vip: the Gateway Service has no class there and ServiceLB publishes it.
    • No cilium, homelab-public, cilium-gateway-* or namespace: gateway reference may remain outside docs/superpowers/ (history).
    • Spec deviations already ruled while planning (recorded in Task 3's commit message and the spec): Gateway API standard channel (v1.6.3 ships TCPRoute there, and Istio 1.31 serves TCPRoute and BackendTLSPolicy without PILOT_ENABLE_ALPHA_GATEWAY_API), so the alpha flag is not set; the Gateway's production IP is the kube-vip annotation kube-vip.io/loadbalancerIPs on its Service (through the parametersRef ConfigMap) instead of spec.addresses.
    • Istio's chart repository is https://blob.istio.io/istio-release/charts (the old istio-release.storage.googleapis.com index stops at 1.30.5 and 1.31 release candidates); a scratch render of base + istiod 1.31.1 from it gave docker.io/istio/pilot:1.31.1, pilot.resources applied, and the webhooks istiod-default-validator and istio-validator-istio-system.
    • Spike done while planning (2026-10-14), so the spec's fallback applies: a port published by k3d (Docker) answered 200 from WSL but timed out from Windows (curl.exe and PowerShell through WSL interop; mirrored networking: Docker DNATs the loopback traffic and the kernel drops it). A host-network socat bound to 127.0.0.1 and forwarding to the k3d node IP answered 200 from Windows, and WSL reached the node IP directly. kubectl reached k3d's API on 0.0.0.0:<port> from WSL, so the kubeconfig needs no rewrite. Hence: no k3d port mapping; socat 127.0.0.1:{80,443,22} → node IP (browser, SSH); tests dial the node IP directly (no socat stalls, as today).
    • Branch feat/k3d-istio from dev, PR into dev; ask before merging. KUBECONFIG=$PWD/metal/kubeconfig.yaml for kubectl.

    Review Focus

    1. Argo CD drift on Istio's webhooks: istiod patches caBundle and failurePolicy into its ValidatingWebhookConfigurations, which would keep istio-system OutOfSync or flap. Expected: Synced and stable. Pinned in Task 3 (ignore rule in argocd-cm plus RespectIgnoreDifferences=true) and checked in Task 7 (the Argo CD sync check).
    2. First sync ordering on a fresh cluster: Gateways need the istio GatewayClass, which istiod creates after it starts. Expected: Argo CD retries until the Gateways are accepted; no manual step. Checked in Task 7 (fresh make dev).
    3. CoreDNS rewrite: coredns-custom must be picked up by k3s's CoreDNS without editing the Corefile, or every pod-to-Kanidm call fails. Pinned in Task 3 (render check of the ConfigMap key nip-io.override) and checked in Task 7 (identity and SSO tests).
    4. Host ports 80/443/22 on 127.0.0.1, and a node IP that changes when the cluster is recreated: the proxy must point at the current node and refuse with a clear message when another process holds a port. Pinned in Task 1 (the proxy is recreated on every make dev and the port guard is tested).
    5. Production render: no Cilium flag left in the k3s config, kube-vip serves only its class, the Gateway Service gets the class and IP annotation in production and neither in the sandbox. Pinned by the render checks in Tasks 2 and 3.

# like production; Istio serves the Gateways (system/istio-system). No host port mapping: under WSL mirrored
# networking Windows cannot reach ports Docker publishes, so metal/Makefile runs a localhost proxy instead.
apiVersion: k3d.io/v1alpha5

metadata:
  name: homelab-dev
servers: 1
agents: 0
image: rancher/k3s:v1.37.1-k3s1
options:
  k3s:
    extraArgs:
      - arg: --disable=traefik
        nodeFilters: [server:*]
      # Embedded etcd, like production
      - arg: --cluster-init
        nodeFilters: [server:*]
      # Control plane metrics for kube-prometheus-stack
      - arg: --etcd-expose-metrics
        nodeFilters: [server:*]
      - arg: --kube-controller-manager-arg=bind-address=0.0.0.0
        nodeFilters: [server:*]
      - arg: --kube-scheduler-arg=bind-address=0.0.0.0

    • Step 4: Rewrite metal/Makefile

    Replace the line dev: kind cluster proxy with dev: k3d proxy, and everything from kind_cluster = homelab-dev to the end of the file with:

    k3d_cluster = homelab-dev
k3d_node = k3d-$(k3d_cluster)-server-0
gateway_api_version = v1.6.3
gateway_api_manifest = gateway-api-$(gateway_api_version).yaml

# Gateway API CRDs for k3s's auto-deploy manifests (production: roles/k3s)
$(gateway_api_manifest):
    curl -fsSL -o "$@" https://github.com/kubernetes-sigs/gateway-api/releases/download/$(gateway_api_version)/standard-install.yaml

k3d: $(gateway_api_manifest)
    k3d cluster list $(k3d_cluster) >/dev/null 2>&1 \
        || k3d cluster create --config k3d-dev.yaml \
            --volume "$(CURDIR)/$(gateway_api_manifest):/var/lib/rancher/k3s/server/manifests/gateway-api.yaml@server:*"
    k3d kubeconfig get $(k3d_cluster) > kubeconfig.yaml

proxy_name = homelab-dev-proxy
proxy_bind = 127.0.0.1

# ServiceLB publishes the Gateway (system/istio-system) on the node; Windows reaches WSL's 127.0.0.1 only
# through a host process, so forward 80, 443 and 22 there. Recreated each time: the node IP can change.
proxy:
    @docker rm -f $(proxy_name) >/dev/null 2>&1; \
    if ss -ltnH '( sport = :80 or sport = :443 or sport = :22 )' | grep -q .; then \
        echo "ports 80/443/22 are already in use on this host:"; ss -ltnp '( sport = :80 or sport = :443 or sport = :22 )'; exit 1; \
    fi; \
    node="$$(docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' $(k3d_node))"; \
    docker run -d --name $(proxy_name) --network host --restart unless-stopped \
        --entrypoint sh alpine/socat:1.8.1.3 -c "\
            socat TCP-LISTEN:80,bind=$(proxy_bind),fork,reuseaddr TCP:$$node:80 & \
            socat TCP-LISTEN:22,bind=$(proxy_bind),fork,reuseaddr TCP:$$node:22 & \
            exec socat TCP-LISTEN:443,bind=$(proxy_bind),fork,reuseaddr TCP:$$node:443" >/dev/null

clean:
    docker rm -f $(proxy_name) >/dev/null 2>&1 || true
    k3d cluster delete $(k3d_cluster)
    rm -f kubeconfig.yaml

    #!/bin/sh
# system/istio-system renders: Istio, two Gateways, kube-vip only in prod, CoreDNS rewrite only in dev

prod=$(scripts/render-chart system/istio-system 2>/dev/null)
n=0
check() { echo "$3: $1"; test "$1" = "$2"; n=$((n+1)); }
check "$(echo "$dev" | yq ea '[select(.kind == "Gateway") | .metadata.name + ":" + ([.spec.listeners[].name] | join(","))] | join(" ")')" "gateway:http,https,ssh public:https" "gateways"
