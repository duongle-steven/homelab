    Policy (Step 15b-1) Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Kyverno in Audit with the restricted Pod Security policies, pinned images and allowed registries. A policy basic check blocks violations in CI. Every fixable workload is fixed, every inherent one has a written exception, and PSA baseline is the second layer.

    Architecture: - system/kyverno wraps the kyverno and kyverno-policies charts (3.9.2) and adds two custom ValidatingPolicy objects. - scripts/check-policy runs the kyverno CLI on every render. - Exceptions are PolicyExceptions in the excused component's own chart or app file.

    Tech Stack: Kyverno 1.19.2 (CEL ValidatingPolicy), Helm, POSIX sh, Go tests.

    Spec: docs/superpowers/specs/2026-10-27-policy-design.md

    Global Constraints

    • Charts kyverno 3.9.2 and kyverno-policies 3.9.2. The kyverno CLI 1.19.2 comes from unstable, since nixos-26.05 ships 1.18.2.
    • The policies are Audit in the cluster, and the check fails CI on any fail or error.
    • podSecurityUserNamespaces: true, for Woodpecker's step pods.
    • Every PolicyException names its policies and its workloads, and gives its reason in an annotation.
    • Kyverno's pods carry istio.io/dataplane-mode: none (the API server calls them), and its webhooks use failurePolicy: Ignore.
    • Mesh and egress rules still hold: scripts/check-mesh-policies and scripts/check-env-config pass.
    • scripts/ci-check all, lint and gofmt pass before every commit.

    Review Focus

    1. A fix that breaks an app. A securityContext an image cannot run under (it writes to /, or needs root) must not ship. Test: the sandbox suite (make dev full) passes.
    2. An exception broader than its workload, such as a whole namespace or every policy. Test: TestCheckPolicy fails when the exceptions file is dropped. A review reads each exception's match conditions.
    3. Kyverno down or slow at admission must not block deploys while in Audit (failurePolicy: Ignore). Test: TestPolicy checks the webhook configuration's failurePolicy.
    4. The PSA label on a namespace that needs privileged, set too strictly, would stop its pods on any restart. Test: the sandbox suite (TestNodeRestart restarts every pod).

    Task 1: system/kyverno and the policy check

    Files: - Create: system/kyverno/{Chart.yaml,values.yaml,values-dev.yaml,templates/*.yaml}, scripts/check-policy - Modify: flake.nix (unstable.kyverno), system/argocd/values-dev.yaml (system/kyverno), test/scopes.yaml (system/kyverno/** maps to Policy) - Test: test/policy_test.go (TestCheckPolicy)

    • Step 1: Write the failing test. TestCheckPolicy:
    • with TARGETS set to a fixture chart whose Deployment lacks a securityContext, the check fails and names require-run-as-nonroot;
    • with the fixture's securityContext set, it passes;
    • an image foo:latest fails require-pinned-images;
    • an image from evil.example/x:1 fails allowed-registries.
    • Step 2: Run it. It fails.
    • Step 3: Implement.
    • The chart pins the two subcharts.
    • Settings: kyverno-policies with podSecurityStandard: restricted, validationFailureAction: Audit, podSecurityUserNamespaces: true and failurePolicy: Ignore.
    • Kyverno with webhooks failurePolicy: Ignore, its pods labelled istio.io/dataplane-mode: none, and only the controllers it needs (admission, background, reports, cleanup).
    • templates/images.yaml holds the two custom ValidatingPolicies. The allowed registries are docker.io, ghcr.io, quay.io, registry.k8s.io, gcr.io, code.forgejo.org, public.ecr.aws and registry.<domain>, each checked against the renders.
    • scripts/check-policy:
      • render system/kyverno for the policies;
      • collect the PolicyExceptions from every render;
      • collect the workloads (Deployment, StatefulSet, DaemonSet, Job, CronJob, Pod) from each target's render, both environments; TARGETS overrides the list, otherwise every chart and app file;
      • run kyverno apply ... --exception ... --policy-report, and fail on fail or error results, printing policy, kind and name.
    • Step 4: Run it. The test passes. scripts/render-chart system/kyverno dev renders. scripts/check-policy on the whole repository lists today's violations; it is not in ci-check yet.
    • Step 5: Commit. feat(kyverno): Kyverno in Audit with restricted Pod Security, pinned images and allowed registries; scripts/check-policy

    Task 2: Fix the workloads, write the exceptions

    Files: the charts' values.yaml and app files that scripts/check-policy names, plus templates/policy-exception.yaml in each chart that needs one, or rawResources in an app file.

    • Step 1: The failing check. scripts/check-policy lists the violations: the red state.
    • Step 2: Fix each workload where its image allows it.
    • app-template apps: defaultPodOptions.securityContext (runAsNonRoot, runAsUser/runAsGroup/fsGroup from the image's user, seccompProfile: RuntimeDefault), plus per-container allowPrivilegeEscalation: false and capabilities.drop: [ALL];
    • upstream charts: their own securityContext values.
    • Step 3: Write a PolicyException for each inherent violation, matched by namespace and workload name:
    • the spike's baseline list;
    • images that run only as root, each named with the reason.
    • Step 4: Run it.
    • scripts/check-policy passes. Add policy to ci-check's checks and to the CI matrix, and TestCheckPolicy to offline_tests.
    • make dev scope=full passes: the fixed apps still run.
    • Step 5: Commit, in small commits by area: mesh and system, platform, apps.

    Task 3: Pod Security Admission

    Files: system/argocd/values.yaml and values-dev.yaml (the shared managedNamespaceMetadata, and the root templatePatch for the privileged namespaces), plus whatever the apps ApplicationSet needs.

    • Step 1: Write the failing test. TestPolicy (sandbox), PSA part:
    • namespace excalidraw has pod-security.kubernetes.io/enforce=baseline;
    • a privileged pod created there with --dry-run=server is refused;
    • istio-system has privileged.
    • Step 2: Implement. Label the namespaces from Task 2's baseline exceptions privileged, and every other managed namespace baseline. Argo CD's own namespace is baseline.
    • Step 3: Run it. make dev tests='Policy' passes, and TestNodeRestart still passes.
    • Step 4: Commit. feat: Pod Security Admission baseline on every managed namespace, privileged where an exception needs it

    Task 4: Kyverno in the sandbox, docs, review, PR

    • Step 1: The sandbox test. TestPolicy, Kyverno part:
    • Kyverno's admission controller is Ready, and its ValidatingWebhookConfiguration uses failurePolicy: Ignore;
    • a pod breaking restricted (no securityContext), created in a test namespace labelled baseline, is admitted (Audit), and a PolicyReport for it shows fail within 2 minutes;
    • no PolicyReport in the cluster has a fail for a repository workload: Audit is clean, which is 15b-2's precondition.
    • Step 2: Docs.
    • docs/reference/architecture/ or a new docs/how-to-guides/policy.md: the policies, how to write an exception, the policy check.
    • CLAUDE.md: 15b-1 done; the mesh bullet notes Kyverno is outside the mesh; a Rules line saying a new workload sets its securityContext or adds an exception.
    • deferred-minors.md.
    • Step 3: Run, review, PR.
    • scripts/ci-check all and make dev scope=full.
    • A fresh reviewer agent reviews the branch; fix Critical and Important.
    • Open the PR into dev.
