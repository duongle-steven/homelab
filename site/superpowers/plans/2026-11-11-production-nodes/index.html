    Production's Nodes (12b-1) Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: NixOS and one k3s cluster of three servers on the three HP mini PCs, installed from the network, and the hardware proofs: DNS, fio, kube-bench, the VIP moving with Wake-on-LAN, a power cut.

    Architecture: - The node flake reads two new config.json fields, disk and network.dns. - infra/production/metal mirrors infra/testbed/metal, but nixie writes its record into the committed hosts.json (upstream's way). - The testbed's node specs also run on production. Two new specs, which stop nodes, carry a label hardware-proof that a routine production run never selects. - The install and the proofs are run by hand with the person, who provides the SSH key, the Hyper-V firewall rules, Cloudflare's login and the power strip.

    Tech Stack: - Nix (the node flake) and Terragrunt/OpenTofu (the metal unit); - nixie and nixos-anywhere, lab cluster; - Ginkgo (test/e2e), testify (test/offline), just.

    Spec: docs/superpowers/specs/2026-11-11-production-nodes-design.md

    Global Constraints

    • Nodes:
    Node IP MAC
    homelab-1 (init_host) 192.168.0.11 38:22:e2:2c:dc:35
    homelab-2 192.168.0.12 10:62:e5:16:d2:ca
    homelab-3 192.168.0.13 10:e7:c6:0f:63:a0

    The API's VIP is 192.168.0.10. - Disk: /dev/nvme0n1 for every production node, from config.json's disk. Never in hosts.json: nixie drops unknown fields. - DNS: - production's config.json gets "network": {..., "dns": ["192.168.0.1"]}; - without network.dns, the nodes keep 8.8.8.8 and 1.1.1.1, so the testbed is unchanged; - budget: an NXDOMAIN and an AAAA-less name answer in under 1 s from a node and from a pod. - Install record: nixie writes machine_id_hash into infra/production/metal/hosts.json, and it is committed. The testbed keeps .state/testbed/ unchanged. - Host keys: trusted on first contact for hosts.json's addresses only (scripts/testbed-trust, reused). - Spec label: hardware-proof marks specs that power off nodes. just test e2e --env production with no --labels runs production && !hardware-proof && !scan. - fio: etcd's pattern --rw=write --ioengine=sync --fdatasync=1 --bs=2300 --size=22m, with a p99 fdatasync budget of 10 ms. - Never: - install a MAC not in hosts.json; - leave the Hyper-V rules after the install; - run just dev beside the testbed or with less than 30 GB free on C:; - commit to dev or master. - Commits end with the session's Co-Authored-By and Claude-Session lines.

    Review Focus

    1. A routine just test e2e --env production never powers off a node.
    2. Expect the default filter to exclude hardware-proof and scan, and --labels to still allow running them on purpose.
    3. Task 3 pins it with a dry-run (ginkgo --dry-run).
    4. A recorded host is never reinstalled.
    5. Expect nixie to get the repository's hosts.json itself, never a copy.
    6. Expect the record committed after the install.
    7. Task 2 pins it with an offline test on the unit's hook arguments.
    8. A node's own disk still wins over config.json's, and the testbed's VMs stay on /dev/sda. Task 1's fixture covers both.
    9. Wake-on-LAN from WSL over Wi-Fi may not reach a wired node.
    10. Expect the VIP spec to fail and name Wake-on-LAN.
    11. Expect a woken node with no nixie running to fall back to its NVMe.
    12. Task 5 runs it on the hardware.
    13. The power cut proves the nodes, not data. Expect the docs not to claim acknowledged writes survive (12b-2 does); Task 6 words it.

    Task 3: The specs run on production, and stop nodes only when asked

    Files: - Modify: test/e2e/testbed_test.go. - testbedHosts() becomes metalHosts(), which reads infra/<metalEnv()>/metal/hosts.json. - metalEnv() returns testbed when ENV=testbed, and production when ENV is empty (just test e2e --env production). - Callers are renamed. - Modify: Describe("TestbedNodes"), Describe("TestbedSecretsEncrypted") and Describe("TestbedSeccomp") take the label production too. - Modify: test/e2e/scan_test.go: ScanBench takes production. - Create: test/e2e/production_test.go: - Describe("NodesResolveQuickly", Label("production")) (production only: the testbed's VMs also query 8.8.8.8 through NAT and may meet the same interception, a deferred minor, not this step's). On every node over SSH, and from a busybox pod in a scratch namespace, it times nslookup of nx-<random>.example.com (NXDOMAIN) and of ipv4only.arpa's AAAA. Each answers in under 1 s. The time is measured inside the node or pod (date +%s%N before and after), not around SSH. - Describe("ProductionVIPMoves", Label("production", "hardware-proof"), Serial). - It finds the VIP's holder (lease plndr-cp-lock) and records its bootID. - It runs systemctl poweroff over SSH and waits up to 2 minutes for /readyz through the VIP, and for the holder to change. - It then sends Wake-on-LAN to the stopped node's MAC with wakeOnLAN(mac string) error: a magic packet to UDP 255.255.255.255:9. - It waits up to 10 minutes for a new bootID and Ready. - On a timeout the message names Wake-on-LAN and asks the person to press the button. - Describe("ProductionPowerCut", Label("production", "hardware-proof"), Serial). - It records every node's bootID and prints "switch the power strip off, wait 30 s, switch it on". - It then waits up to 30 minutes for every node to report a new bootID and Ready, and for /readyz through the VIP. - It prints the duration from the first API failure to all Ready. - Modify: test/justfile e2e: for production with no --labels, the filter is production && !hardware-proof && !scan. - Modify: test/scopes.yaml: add label hardware-proof to labels:. - Test: the dry runs below, and TestE2EKeepsSelection.

    Task 4: The install on the hardware (by hand, with the person)

    Files: - Modify: infra/production/metal/authorized_keys. - Modify: infra/production/metal/hosts.json (nixie's record).

    • Step 1: The person.
    • Makes the key: ssh-keygen -t ed25519 -f ~/.ssh/homelab-production with a passphrase, then ssh-add it.
    • Pastes the public key into authorized_keys, which is committed.
    • Adds the two Hyper-V firewall rules (spec decision 2).
    • Logs in to Cloudflare (cf auth login) for production's state.
    • Switches the three machines off.
    • Step 2: RED. just test e2e --env production --labels 'production && !hardware-proof'. Expected: FAIL (no kubeconfig, no nodes).
    • Step 3: Install. HOMELAB_PXE_ADDRESS=<laptop's LAN IP> and cd infra/production/metal && terragrunt apply. Expected:
    • nixie wakes, installs and records the three machines;
    • trust, enroll and kubeconfig succeed;
    • kubectl get nodes shows three Ready servers.

    If a machine does not wake, the person presses F12 on it. - [ ] Step 4: The person removes the Hyper-V rules. Commit hosts.json (the record) and authorized_keys: feat(12b-1): production's nodes installed. - [ ] Step 5: GREEN. The same command as step 2. Expected: PASS (nodes, secrets encrypted, seccomp, DNS, kube-bench's scan with its accepted list). A new kube-bench FAIL is triaged into .cluster-scan-accepted.yaml or fixed. - [ ] Step 6: Rerun terragrunt apply. Expected: nixie sees every host recorded and does not start; upgrade finds every node up to date.

    Task 5: The hardware proofs

    Files: - Create: scripts/node-fio <ip>. Over SSH as root, it runs fio from nix shell nixpkgs#fio: - etcd's pattern in /var/lib/rancher; - sequential and random 4k on the rook-data partition, then blkdiscard on it so Ceph finds it empty.

    It prints the p99 fdatasync and the throughputs. - Modify: docs/installation/production/deployment.md: a "Measured" section with the numbers.

    • Step 1: scripts/node-fio on each node. Expected: a p99 fdatasync for every node, recorded. A node over 10 ms is recorded as a finding for 12b-2, not fixed here.
    • Step 2: just test e2e --env production --labels hardware-proof --focus ProductionVIPMoves. Expected: the VIP moves, and the node wakes by Wake-on-LAN and falls back to its NVMe. If it does not wake, record it and the person presses the button.
    • Step 3: --focus ProductionPowerCut, with the person at the power strip. Expected: every node back by itself; the duration recorded.
    • Step 4: After the cut, check that each node's first boot entry is NixOS's (efibootmgr over SSH), and delete the stale Windows Boot Manager entries (efibootmgr -b <n> -B).
    • Step 5: Commit docs(12b-1): the hardware's numbers.
