    Staging platform (12a-2) Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Argo CD, the platform and as many apps as fit run on staging through production's deploy path, and a release that changes what staging runs needs staging's mark.

    Architecture: A shared values layer (values-local.yaml) gives staging and the sandbox the local CA and the tests' fixtures; staging's Argo CD is production's set minus an exclusion list in system/argocd/values-staging.yaml, bootstrapped from GitHub branch staging, then switched to ops/homelab on staging's Forgejo. make staging runs the suite there and writes a GitHub commit status staging; lab infra forgejo verify derives the gated paths and looks for that mark.

    Tech Stack: Helm, Argo CD ApplicationSets, OpenTofu/Terragrunt, Go (cli/, test/), POSIX sh, yq, gh.

    Spec: docs/superpowers/specs/2026-11-01-staging-platform-design.md

    Global Constraints

    • Prerequisite: the pull request removing ollama is merged into dev, and this branch is rebased on it.
    • Ideally staging is production; the reduction is one exclusion list, nothing else differs except values-staging.yaml where staging must.
    • Layers: production values.yaml; staging values.yaml, values-local.yaml, values-staging.yaml; sandbox values.yaml, values-local.yaml, values-dev.yaml.
    • The sandbox's renders are identical before and after the split.
    • Fallback order: drop apps; squeeze the core (Ceph's OSD toward 900 MB, Prometheus off); 3.75 GB per VM with WSL at 12 GB; WSL at 13 GB. Three nodes and Istio stay. Whatever is left out goes in the exclusion list; 12a-2 ships with what fits.
    • Gated paths: infra/staging/release-paths.yaml plus every component and app staging deploys (production's set minus the proved commit's exclusion list). Compared against ops/homelab's master on Forgejo; no Forgejo: all changed.
    • The mark needs every test green, the destructive ones included (TestBackupRestore, TestNodeRestart, TestRotation).
    • CLAUDE.md's rules: pinned latest versions, config.json for environment settings, the secrets catalog, backup labels, PolicyExceptions, mesh policies, test/scopes.yaml, deferred minors. Never print secrets; never run make staging or make dev from a worktree; staging and the sandbox never run together.

    Review Focus

    • A release where only a docs file changed after the mark: verify passes without a rerun (Task 6's TestStagingGateAcceptsEarlierMark).
    • A release that changes an excluded app only: no mark needed; a release that empties the exclusion list: every component counts (Task 6's TestStagingGateExcludedApp, TestStagingGateUsesProvedExclusions).
    • A first production install with no Forgejo: everything counts as changed, so the mark is required (Task 6's TestStagingGateNoDeployedCommit).
    • --skip-staging with an empty or blank reason: refused (Task 6's TestSkipStagingNeedsReason).
    • A staging run interrupted after the switch to Forgejo: the next make staging keeps Argo CD on Forgejo, never back to the seed (Task 3: choose-values.sh's existing rule, asserted by TestStagingBootstrapKeepsForgejo).

What only the one-node sandbox needs (retentions, sizes, worker counts, the hostpath CSI, the CoreDNS rewrite of *.127-0-0-1.nip.io, retries) stays in values-dev.yaml. - Modify: scripts/render-chart (load values-local.yaml for every env but prod, before values-<env>.yaml), scripts/env-values (accept staging), system/argocd/values-dev.yaml (root's valueFiles: values.yaml, values-local.yaml, values-dev.yaml), scripts/check-* that list values files - Create: scripts/compare-renders (renders every component and app for an env at two revisions with scripts/render-chart, prints differing names; exit 1 on any) - Test: test/values_layers_test.go

    Interfaces: - Produces: - func GatedPaths(root, provedCommit string) ([]string, error): release-paths.yaml's globs plus system/<x>/**, platform/<x>/**, apps/<x>.yaml, apps/<x>/** for every component production deploys that the proved commit's values-staging.yaml does not exclude - func StagingGate(ctx, root, repository, deployed, release string, candidates []string, gh GitHub) error: deployed empty means everything changed; passes when a candidate (newest first) has status staging success and git diff --name-only <candidate> <release> touches none of GatedPaths(root, candidate), or when git diff --name-only <deployed> <release> touches none - func (g GitHub) CommitStatus(ctx, repository, sha, context string) (string, error) (state, "" if none) - scripts/staging-mark <sha>: gh api repos/<repo>/statuses/<sha> with context staging, state success - verify --skip-staging=<reason>: refused when blank; prints the reason and records it as status staging success with description skipped: <reason> on the release commit through scripts/staging-mark
