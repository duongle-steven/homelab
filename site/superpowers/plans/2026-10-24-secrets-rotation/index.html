    Secrets Rotation (Step 11b) Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: lab secrets rotate <name>|--all replaces any secret in a catalog by its official method (overlap when the other side allows it), a daily CronJob rotates the due ones, and a failure alerts through ntfy and Telegram.

    Architecture: - A new Go package cli/internal/rotate holds the catalog (an embedded YAML), the engine (safety checks, ordering, the record) and one Method per kind of secret. - Refreshing ExternalSecrets, restarting workloads and waiting for them move out of cli/internal/backup into cli/internal/workload, which both use. - The CronJob (platform/secrets-rotation) runs lab secrets rotate --scheduled from the lab image, which GitHub Actions builds with ko.

    Tech Stack: Go (cobra, client-go, github.com/openbao/openbao/api/v2, the Forgejo SDK already in cli/), ko, Helm charts as in platform/, Alertmanager telegram_configs, Terragrunt/OpenTofu for Cloudflare's tokens.

    Spec: docs/superpowers/specs/2026-10-24-secrets-rotation-design.md

    Global Constraints

    • Latest stable release of every tool, chart, image and Go module, pinned exactly (images by digest when they have no version tag); hold one back only for a stated compatibility constraint.
    • No secret value in git, command arguments, logs, error messages or test output: errors name the path, never the value (as cli/internal/secrets does). The Telegram chat id is treated as a secret.
    • Branch feat/secrets-rotation from dev; PR into dev; never commit to dev or master.
    • Before each commit: direnv exec . scripts/ci-check all passes. Run make dev only from /home/nixos/homelab, never from a worktree. The last make dev before the PR covers the whole branch, and a make dev-fresh at the end.
    • A new component gets its entry in test/scopes.yaml in the task that adds it.
    • Every commit ends with the attribution lines of the session's system reminder.
    • Settings that depend on the environment come from infra/<env>/cluster/config.json globals; charts hold no domain or address.
    • Deferred minors go in docs/superpowers/deferred-minors.md; rulings and findings go in the ledger (.superpowers/sdd/2026-10-24-secrets-rotation/progress.md).
    • Tell the user about GitHub Actions runs that would repeat local tests or pile up before adding them (memory flag-ci-compute-cost).

    Review Focus

    1. A rotation interrupted half-way (Ctrl-C, the Job's pod killed, OpenBao restarting) after the new value was written but before every reader switched: rerunning the same command must finish it. It must not create a third value, and with an overlap it must never revoke the old value before the readers moved. Test: TestRotateResumesAfterInterruption (Task 4).
    2. --all or --scheduled reaching a manual entry (GitHub App key, Telegram, Tunnel) without a terminal: skip it and name it in the report, never hang waiting for input. Test: TestRotateSkipsManualWithoutTerminal (Task 4).
    3. A reader that does not come back (its ExternalSecret cannot refresh, its pod crash-loops): stop, keep the old value valid where there is an overlap, and report which reader failed. Test: TestRotateKeepsOldOnReaderFailure (Task 4).
    4. A mistyped name: an error naming the closest catalog names, with nothing touched. Test: TestRotateUnknownName (Task 4).
    5. Values leaking in errors, e.g. an OpenBao or Forgejo error that echoes a request body: every error a method returns is checked to contain no generated value. Test: TestMethodErrorsHideValues (Task 5).

    Task 4: The engine and lab secrets rotate|list

    Files: - Create: cli/internal/rotate/rotate.go, cli/internal/rotate/record.go, cli/internal/rotate/rotate_test.go - Modify: cli/internal/cli/secrets.go, cli/internal/cli/root.go

    Interfaces: - Consumes: Entry, Load, Find (Task 3); workload.Client (Task 2); secrets.Store (existing); backup.Client.Runs (existing). - Produces:

    // A Method changes one entry in phases, so an interrupted run resumes: Prepare writes the new value (or finds the one
// a previous run wrote), Switch moves the readers to it, Verify checks they work, Revoke ends the old value (a no-op
// without an overlap).
type Method interface {
    Prepare(ctx context.Context, e Entry) error
    Switch(ctx context.Context, e Entry) error
    Verify(ctx context.Context, e Entry) error
    Revoke(ctx context.Context, e Entry) error
}
type Options struct {
    All, Scheduled, Yes, Interactive bool
    SkipBackupCheck                  string // the reason; empty = check
    Now                              time.Time
}
type Result struct {
    Name    string
    Outcome string // rotated, skipped (and why), failed (and the phase)
    Err     error
}
type Rotator struct {
    Entries  []Entry
    Methods  map[Method]Method // by entry method
    Store    Records           // record.go
    Backups  func(ctx context.Context) ([]backup.Run, error)
    Idle     func(ctx context.Context, what string) (bool, error)
    Out      io.Writer
    Poll, Wait time.Duration
}
func (r *Rotator) Plan(names []string, o Options) ([]Entry, error) // the order --all uses; unknown names error
func (r *Rotator) Run(ctx context.Context, plan []Entry, o Options) ([]Result, error)
    • Record (record.go): the custom metadata of the entry's first OpenBao path holds the rotation state, through a new secrets.Store.Metadata(ctx, path) (map[string]string, error) and secrets.Store.SetMetadata(ctx, path, map[string]string) error.
    • Keys: rotation-phase (prepared, switched, verified, done), rotated-at (RFC 3339), rotated-by, rotation-method, rotation-reason (the backup-check override).
    • Entries without an OpenBao path (OpenTofu's, GitHub's) use the same keys on secret/rotation/<name>. That path is reachable only by the admin role and the new rotator role (Task 9).
    • Order for --all:
    • generated secrets and ntfy;
    • Forgejo;
    • Kanidm clients;
    • Woodpecker and zot (with the idle wait);
    • OpenTofu's;
    • manual ones last.

    never, script and automatic entries are listed with their reason and skipped. - Run: - checks the backup first: a Completed scheduled run started less than 24 hours before o.Now, unless SkipBackupCheck; - then, per entry: waits for idleness, resumes from the recorded phase, runs the phases, records each one and stops at the first failure; - returns every entry's result. - lab secrets list prints each entry's name, method, class, period, last rotation and next due date. - lab secrets rotate <name>... | --all: - prints the plan, the workloads that will restart (marking those with one replica, which stop briefly) and the people who must act, then asks for confirmation (confirm from cli/backup.go); - --yes skips the confirmation; - --scheduled implies --yes, picks only due entries and skips manual ones; - --skip-backup-check=<reason> overrides the backup check; - exits non-zero when any entry failed or a due entry is past its due date plus 14 days.
