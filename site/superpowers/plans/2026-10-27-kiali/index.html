    Kiali (Step 14d) Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: A read-only Kiali for admins on the LAN Gateway, with Istio's metrics scraped so its graph has data.

    Architecture: - Metrics: system/istio-system gains PodMonitors for ztunnel, istiod and the Gateways' Envoy, and whatever lets Prometheus reach them. - Kiali: a new component system/kiali wraps kiali-server 2.33.0. It signs in with Kanidm's openid and holds its own HTTPRoute, AuthorizationPolicy and Kanidm client.

    Tech Stack: Helm, kube-prometheus-stack's PodMonitor, Istio ambient, kaniop, Go sandbox tests.

    Spec: docs/superpowers/specs/2026-10-27-kiali-design.md

    Global Constraints

    • kiali-server chart 2.33.0 from https://kiali.org/helm-charts, pinned.
    • Kiali has view_only_mode: true and disable_rbac: true. Only homelab-admins gets a scope on Kanidm client kiali.
    • The route kiali.{{ .Values.global.baseDomain }} is on istio-system/gateway only, never public.
    • No IP address or domain in the chart (scripts/check-env-config).
    • No PVC.
    • The new secret has an entry in cli/internal/rotate/catalog.yaml.
    • scripts/check-mesh-policies passes.
    • scripts/ci-check all runs before each commit. make dev runs only from /home/nixos/homelab.

    Review Focus

    1. A signed-in non-admin (homelab-editors, homelab-users, no group) must not reach Kiali. Test: TestSSOKiali refuses dev-editor, dev-viewer and dev-outsider.
    2. A write through Kiali's API (as an admin) must be refused, since the instance is read-only. Test: TestSSOKiali PATCHes an Istio object through Kiali and expects a refusal.
    3. Kiali on the public Gateway must never render. Test: TestKialiRender (offline) finds exactly one HTTPRoute, with parent gateway.
    4. An empty graph (metrics missing, or Prometheus blocked by the mesh): the graph API must return edges. Test: TestMeshMetrics checks the series, and TestSSOKiali checks the graph has at least one edge.

    Task 1: Istio's metrics in Prometheus

    Files: - Create: system/istio-system/templates/pod-monitors.yaml - Modify: whatever lets Prometheus scrape, if needed: system/istio-system's policies, or monitoring-system's network policy - Test: test/mesh_metrics_test.go; test/scopes.yaml already maps system/istio-system/** to Mesh

    Interfaces: - Produces Prometheus series that Task 2's graph reads: - istio_tcp_sent_bytes_total{reporter="destination"} from ztunnel; - istio_requests_total from the Gateways' Envoy; - pilot_xds_pushes from istiod.

    • Step 1: Write the failing test. TestMeshMetrics(t), sandbox only (meshSandboxOnly). Within 5 minutes, Prometheus's API (exec into the Prometheus pod or port-forward, like the monitoring tests) returns at least one series for each of:
    • istio_tcp_sent_bytes_total
    • istio_requests_total{source_workload="gateway-istio"}
    • pilot_xds_pushes

    Generate traffic first: one request through the Gateway to a smoke app. - [ ] Step 2: Run it. make dev tests='MeshMetrics' fails: no series. - [ ] Step 3: Implement. Write one PodMonitor each for: - ztunnel (app=ztunnel, port 15020, /stats/prometheus); - istiod (app=istiod, port 15014, /metrics); - the Gateways (gateway.networking.k8s.io/gateway-name exists, port 15020, /stats/prometheus).

    Drop envoy_.* series from the Gateways and ztunnel's high-cardinality internal series with metricRelabelings, keeping istio_.*. Open the paths scripts/check-mesh-policies names and add the in-cluster calls to its EXTRA. - [ ] Step 4: Run it. make dev tests='MeshMetrics' passes. The offline render scripts/render-chart system/istio-system dev succeeds. - [ ] Step 5: Commit. feat(istio-system): Prometheus scrapes ztunnel, istiod and the Gateways (Kiali's graph, Grafana)

    Task 2: system/kiali

    Files: - Create in system/kiali/: - Chart.yaml: dependency kiali-server 2.33.0; - values.yaml and values-dev.yaml; - templates/: kanidm-client.yaml, httproute.yaml, authorization-policy.yaml, and the secret mapping if the chart needs one. - Modify: - system/argocd/values-dev.yaml: add system/kiali to root; - platform/kanidm/values.yaml: add kiali to oauth2ClientNamespaces; - system/monitoring-system/templates/authorization-policy.yaml: admit Kiali's service account on Prometheus's 9090; - cli/internal/rotate/catalog.yaml: entry kanidm-client.kiali (kind kaniop-client, settings {client: kiali, namespace: kiali}; class from how Kiali reads the secret: 2 with its Deployment as reader if it reads it at start); - test/scopes.yaml: system/kiali/** maps to SSOKiali|KialiRender; - system/argocd/values.yaml: Argo CD editors' exec list, only if the convention lists system components (it lists apps/*: none expected). - Test: test/kiali_test.go (TestKialiRender offline; TestSSOKiali)

    Interfaces: - Consumes Task 1's series. - Uses appLogin, ensureCredentials, getJSON and waitForApp from the identity helpers.

    • Step 1: Write the failing tests.

    • TestKialiRender(t), offline: render system/kiali (prod and dev) with scripts/render-chart. Assert:

      • exactly one HTTPRoute, whose parent is gateway;
      • the Kiali config has view_only_mode: true, strategy: openid and disable_rbac: true;
      • the KanidmOAuth2Client's scopeMap names only homelab-admins;
      • no PersistentVolumeClaim is rendered.

      Add the test to scripts/ci-check's offline_tests. - TestSSOKiali(t), sandbox: - dev-admin signs in through Kanidm. GET /kiali/api/namespaces returns 200 with kiali in the list. GET /kiali/api/namespaces/graph?namespaces=excalidraw,istio-system&graphType=workload returns at least one edge, retried for up to 5 minutes after one request through the Gateway. - A write as dev-admin (PATCH /kiali/api/namespaces/istio-system/istio/... on an AuthorizationPolicy) does not succeed. - dev-editor, dev-viewer and dev-outsider do not get a Kiali session (Kanidm refuses them: no scope). - [ ] Step 2: Run them. go test -run TestKialiRender fails (no chart). make dev tests='SSOKiali' fails. - [ ] Step 3: Implement. Follow platform/zot's and Grafana's patterns: - the client is confidential: kaniop's Secret kiali-kanidm-oauth2-credentials, key CLIENT_SECRET, mapped to what Kiali reads (oidc-secret); - issuer_uri is https://auth.<baseDomain>/oauth2/openid/kiali, built from global.baseDomain in a wrapper, since the subchart does not template it; - in the sandbox, the dev CA goes through SSL_CERT_DIR; - the Prometheus URL is http://prometheus-operated.monitoring-system:9090; - tracing is off; - the Grafana link points the browser at https://grafana.<baseDomain>, with no Grafana API access; - the chart's deployment.ingress is off. - [ ] Step 4: Run them. - go test -run TestKialiRender passes. - scripts/ci-check all passes: rotation-catalog, mesh, env-config and backup-groups included. - make dev tests='SSOKiali|MeshMetrics' passes. - [ ] Step 5: Commit. feat: Kiali (system/kiali): read-only, admins only, on the LAN Gateway

    Task 3: Docs, the whole run, the PR

    Files: - Create: docs/how-to-guides/kiali.md: what the graph shows (L4 in the mesh, L7 at the Gateways), who can sign in, read-only. Add it to mkdocs.yml's nav. - Modify: - CLAUDE.md: 14d done with a summary. Add a Sandbox bullet (Kiali and the Istio PodMonitors). Add a line to "Before the first production deploy": Kiali was only run in the sandbox, and production series counts are unmeasured. - docs/superpowers/deferred-minors.md: what the review defers.

    • Step 2: Run the checks. scripts/ci-check all, then make dev from the main checkout: its scope covers the whole branch.
    • Step 3: Review and PR. A fresh reviewer agent reads the whole branch. Fix its Critical and Important findings with tests. Open the PR into dev, without the sandbox label, with the rulings and deferred minors.
