    VPN setup

    You can choose between Tailscale, Wireguard, or use both like me. I primarily use WireGuard but keep Tailscale as a backup for when the WireGuard server is down.

    Tailscale (requires third-party account)

    The auth key will come from Headscale (roadmap step 13), which replaces Tailscale's service; until then apps/tailscale.yaml waits for secret/tailscale/auth-key in OpenBao. To use Tailscale's service before that, write a key from the admin console with the admin role (emergency access): bao kv put secret/tailscale/auth-key auth-key=- (the key on stdin).

    Finally, enable subnet routes for homelab-router from the admin console.

    You can now connect to your homelab via Tailscale and invite user to your Tailscale network.

    Wireguard (requires port-forwarding)

    Prerequisites

    Find your public IP address using:

    curl -4 ifconfig.me

    If you don’t have a static IP address, use dynamic DNS and replace the IP with your domain name.

    Next, configure port forwarding in your router for the WireGuard service.

    Example

    Each router is different, here's mine for reference:

    • Protocol: UDP
    • Start Port: 51820
    • End Port: 51820
    • Local IP Address: 192.168.0.3, the wireguard VIP (service_vips.wireguard in infra/production/cluster/config.json; check it with kubectl get service -n wireguard wireguard)
    • Start Port Local: 51820
    • End Port Local: 51820

    The server's key pair comes from OpenTofu (infra/production/secrets): its private key reaches the cluster through OpenBao, and its public key, which every peer needs, is

    cd infra/production/secrets && terragrunt output -raw wireguard_public_key

    I use 172.16.0.0/12 as the private IP range for WireGuard, but you can choose any private IP address range you prefer in ./apps/wireguard.yaml. I also recommend removing my peers and adding your own.

    Add a new device to the server

    Info

    Each device requires its own configuration.

    Generate a new key pair for the device. You can generate it for the user, or they can generate it themselves if they prefer to keep the private key confidential:

    wg genkey | tee /dev/tty | wg pubkey

    This will generate a private key and a public key, in that order. The private key must be saved in a secure password manager, and save the public key for the next step.

    Update the list of peers in ./apps/wireguard.yaml, make sure you replace all of my peers with yours.

    Example

    Example configuration for my phone:

    [Peer]
PublicKey = nITHFdgTkNZOTWeSWqnGXjgwlCJMKRCnnUsjMx2yp2U=
AllowedIPs = 172.16.0.12/32
    • The public key is the one generated in the previous step.
    • 172.16.0.12/32 is the device's private IP address, manually selected from the 172.16.0.0/12 range mentioned above.

    Add the Wireguard config to the device

    Create a new configuration file for the device:

    [Interface]
Address = <CLIENT PRIVATE IP>/32
PrivateKey = <CLIENT PRIVATE KEY>

[Peer]
PublicKey = <SERVER PUBLIC KEY>
Endpoint = <SERVER PUBLIC IP>:51820
AllowedIPs = <SERVER PRIVATE IP>/32, <LOAD BALANCER IP RANGE>

    Replace placeholders with actual values and save as wg0.conf.

    Example

    Example configuration for my phone:

    [Interface]
Address = 172.16.0.12/32
PrivateKey = <REDACTED>

[Peer]
PublicKey = <the server's public key: the homelab peer in apps/wireguard.yaml>
Endpoint = <HOME IP>:51820
AllowedIPs = 172.16.0.1/32, 192.168.0.10/32, 192.168.0.2/32

    Use the vip and service_vips.gateway of infra/production/cluster/config.json in AllowedIPs.

    The client can now import this configuration and connect to your WireGuard mesh. Make sure you clean up the wg0.conf file after importing it to the client.

    Generate a QR code from the configuration file:

    qrencode -t ansiutf8 -r wg0.conf

    Then scan the QR code using the official WireGuard app.

    Import the WireGuard configuration using NetworkManager:

    nmcli connection import type wireguard file wg0.conf

    Activate the connection:

    nmcli connection up wg0

    Headscale

    Headscale is a self-hosted implementation of the Tailscale control server that does not require a third-party account. To set it up, take a look at the changes proposed by this PR.
