# Testbed (12a-2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the workstation's "staging" into a light `testbed` that proves what needs several nodes, make a real staging optional, prove Argo CD reading Forgejo on the sandbox, and make the release gate name which environment proved a release.

**Architecture:** New commits on top of the branch's earlier attempt, which stays as history: rename first, then remove what the design drops, then the testbed's first layer, the generic gate, the sandbox's deploy test, the measured layers and the docs. The testbed's Argo CD syncs GitHub branch `testbed` from an allow-list in `system/argocd/values-testbed.yaml`; the gate reads `infra/<env>/release-paths.yaml` and `system/argocd/values-<env>.yaml` for the environment production's `config.json` names.

**Tech Stack:** Helm, Argo CD ApplicationSets, OpenTofu/Terragrunt, NixOS, libvirt, Go (`cli/`, `test/`), POSIX sh, yq, `gh`.

**Spec:** `docs/superpowers/specs/2026-11-02-testbed-design.md`

## Global Constraints

- Environments: `sandbox` required; one of `testbed` or `staging` proves releases; a staging never loads `values-local.yaml`.
- Values: production and staging load `values.yaml` (then `values-staging.yaml`); testbed `values.yaml`, `values-local.yaml`, `values-testbed.yaml`; sandbox `values.yaml`, `values-local.yaml`, `values-dev.yaml`.
- The sandbox's renders stay identical (check with `scripts/render-all`; apps' and Kanidm's differ run to run).
- Testbed: three VMs of 3.5 GB, 2 vCPUs, at most 4 vCPUs; WSL 13 GB with 4 GB swap; no image cache; no Forgejo; no OpenBao.
- Layer bar: from `make testbed-fresh`, over 30 minutes after the last Application is healthy: no k3s restart, no etcd leader change, no API or lease error, WSL at least 2 GB available (revised by the user 2026-11-03; heartbeat warnings are counted).
- Layer 1 is the floor: if it fails at 4 vCPUs, stop and ask the user; do not relax the bar or ship without it.
- A run stopped for low memory is not restarted without asking. Stop by hand when WSL falls under 1.5 GB.
- Live runs only from the main checkout; testbed and sandbox never together; `ci-check all` only with both stopped.
- `release_proof` is required in production's `config.json`; `--skip-proof=<reason>` needs a non-blank reason.
- `CLAUDE.md`'s rules apply: pinned versions, `config.json`, catalog, backup labels, policy, mesh, `test/scopes.yaml`, deferred minors.

## Review Focus

- `make testbed-fresh` on a cluster that never came up, or with the VMs stopped: `testbed-clean` still removes everything (Task 1 keeps `staging-clean`'s recipe; run live in Task 6).
- A renamed path left behind (`infra/staging`, `scripts/staging-*`, `TestStaging`, branch `staging`): no reference survives outside the old specs and plans (Task 1's `TestNoStagingLeftovers`).
- Production's `config.json` without `release_proof`, or naming an unknown environment: `verify` refuses and says what to set (Task 4's `TestLoadReleaseProof`).
- A release that only changes something in `not_run`, and one that brings it back: the first needs no mark, the second does (Task 4's `TestProofGateNotRun`).
- The temporary Application of the deploy test left behind by a failing run: the next run still passes and nothing stays (Task 5's cleanup in `TestForgejoArgoCDSyncs`).
