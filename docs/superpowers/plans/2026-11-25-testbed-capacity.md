# The Testbed Fits the Workstation Again Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each environment applies only the CRDs it needs (production and the testbed; the sandbox keeps all), and the testbed's VMs are 3 GB with 4 vCPUs.

**Architecture:**
- A new `lab crds generate|check` writes `system/crds/environments/<env>.txt` for `prod` and `testbed`. Each file lists the CRD files under `system/crds/files/` the environment needs:
  - the files of the components its root ApplicationSet deploys;
  - the files whose group and kind its renders (components and apps) use.
- `apply-crds.sh` takes the environment and applies only that list, or every file when there is no list (the sandbox, `dev`).
- The basic check `crds` also runs `lab crds check`.

**Tech Stack:** Go (`cli/`, cobra, yaml.v3; `scripts/render-chart` for the renders), POSIX sh, Terraform variables.

**Spec:** `docs/superpowers/specs/2026-11-25-testbed-capacity-design.md`

## Global Constraints

- Environment names are `scripts/env-values`' names: `prod`, `testbed` and `dev`. The bootstrap's `ENVIRONMENT` is one of them, and the seed is production, so it uses `prod`.
- A CRD is never deleted by any script: an environment's list only chooses what is applied.
- The sandbox (`dev`) applies every CRD. Write no `dev.txt`; its absence means "all".
- Built-in groups need no CRD: the core group, groups ending in `.k8s.io`, and rook-ceph's own `csi.ceph.io`. These are `TestEveryKindHasItsCRD`'s rules.
- A component's CRD files are `system/crds/files/<the component directory's basename>/*.yaml`.
- The testbed's VMs default to `memory_mib = 3072` and `vcpus = 4`, with the reasons beside them.
- Stop before any step that runs the sandbox or the testbed: the user said so (2026-11-25).

## Review Focus

1. **A chart renders a kind whose owner the environment does not run**, for example a `ServiceMonitor` where there is no Prometheus. Expected: that CRD is in the list. Pinned in Task 1's test.
2. **A component is added to an environment's list and the CRD list is not regenerated.** Expected: `lab crds check` fails in the basic checks. Pinned in Task 1.
3. **A running cluster that has more CRDs than its list.** Expected: nothing is deleted; the guide says to remove them by hand once. Pinned in Task 2's docs.
4. **The bootstrap on production's first install, which uses the seed.** Expected: `prod`'s list. Pinned in Task 2's test of the bootstrap's call.
5. **An app file that uses a CRD kind**, such as `ExternalSecret`. Expected: it is counted in production's renders. Pinned in Task 1's test, through the apps ApplicationSet's files.
