# Step 12a-3 power Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The homelab comes back by itself after every node loses power, and stops and restarts in order when someone chooses to.

**Architecture:** `lab cluster shutdown` (Go, from the workstation, beside `cluster.Upgrade`) records what it changes in a ConfigMap marker, stops what runs and powers the nodes off. One script in the node flake undoes it, run by a systemd unit at boot on every node and over SSH by `lab cluster startup`. Live tests on the testbed cut all three VMs and prove recovery.

**Tech Stack:** Go (cobra, `cli/internal/cluster`), NixOS (`writeShellApplication`, systemd), bash, Go tests with terratest (`test/`), virsh.

**Spec:** `docs/superpowers/specs/2026-11-04-power-design.md`

## Global Constraints

- From the main checkout only. Never beside the sandbox; `C:` keeps 30 GB free; stop by hand when WSL falls under 1.5 GB; a run stopped for low memory is not restarted without asking the user.
- Before any testbed or sandbox command: `pgrep -x terragrunt; pgrep -x make`. No foreground `sleep` (`timeout N tail -0f /dev/null`, or background). Absolute `KUBECONFIG` paths. Never `make -n`.
- `virsh destroy` only on `homelab-1|2|3`.
- Do not run `scripts/ci-check all` while the sandbox or testbed is up.
- Names: marker ConfigMap `kube-system/cluster-shutdown`; label `homelab/power-keep: "true"`; script and command on the nodes `cluster-startup`; unit `cluster-startup.service`; probe namespace `power-probe`.
- Values from the spec: Job wait 5 minutes by default; `noout` off when every OSD is back or after 30 minutes at most; recovery limit 30 minutes; startup acts when a majority of the marker's nodes are on a new boot; CloudNativePG measurement at 2 vCPUs.
- Commit trailers: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, `Claude-Session: https://claude.ai/code/session_01DkFEsNWboxteok4WLPJh6q`.

## Review Focus

- A second `lab cluster shutdown` after a partial one: the marker keeps the first run's controller replicas and CronJob names, never replaces them with what is now suspended or zero (test in Task 1).
- The API away for a long time at boot: the script keeps trying and never exits as if there were no marker (test in Task 2).
- A joiner not yet enrolled, with no `/etc/rancher/k3s/k3s.yaml`: the unit exits 0 and does not loop (test in Task 2).
- A CronJob named by the marker removed from git meanwhile, or another node deleting the marker mid-run: NotFound is success, the run finishes (test in Task 2).
- The script restarted, or run by another node, while `noout` waits: the 30 minutes count from the first start, kept in the marker, not from each restart (test in Task 2).

### Task 2: the startup script, its unit and `lab cluster startup`

**Files:**
- Create: `infra/_modules/metal/flake/profiles/cluster-startup.sh`, `infra/_modules/metal/flake/profiles/cluster-startup.nix`, `cli/internal/cli/cluster_startup.go`, `cli/internal/cluster/startup.go`, `test/cluster_startup_test.go`
- Modify: `infra/_modules/metal/flake/default.nix` (modules list), `cli/internal/cli/root.go:30`, `scripts/ci-check` (`offline_tests`)

**Interfaces:**
- Consumes: the marker keys from Task 1.
- Produces: `cluster-startup [--force]` on every node, exit 0 once undone or with nothing to do; `func Startup(ctx context.Context, environment string, progress io.Writer) error`.

The script's order:

```
no /etc/rancher/k3s/k3s.yaml            -> exit 0 (a joiner not enrolled)
get marker: NotFound -> exit 0; any other error -> retry every 15 s, no limit
without --force: a majority of the marker's nodes on a new boot? no -> exit 75 (the unit tries again)
record startup-began if absent
resume the marker's CronJobs (NotFound is success)
scale the controller back to the marker's replicas
every OSD Ready, or NOOUT_LIMIT (1800 s) since startup-began -> unset noout (no CephCluster: skip)
report CloudNativePG Clusters not healthy, holding nothing back
delete the marker (NotFound is success)
```

The first nodes to boot may see no majority yet, so exit 75 is a retry: the unit sets `RestartForceExitStatus=75`, `RestartSec=30`. Once the marker is gone, every retry exits 0. A single node rebooting during a shutdown retries until the shutdown powers it off.

- [ ] **Step 1: Write the failing tests** in `test/cluster_startup_test.go`: bash runs the script with `KUBECTL` pointing at a fake that logs each call and answers from a temp directory; `K3S_YAML`, `NOOUT_LIMIT` and the retry interval are overridable by environment. Each test asserts the fake's log:
  - `TestClusterStartupNoK3s`: no `K3S_YAML`: exit 0, kubectl never called.
  - `TestClusterStartupNoMarker`: NotFound: exit 0, nothing changed.
  - `TestClusterStartupAPIAway`: the first 3 calls fail with connection refused, then the marker exists: it retried and undid everything.
  - `TestClusterStartupMinorityRebooted`: one of three on a new boot: exit 75, nothing changed; with `--force`: undone.
  - `TestClusterStartupUndoes`: the named CronJob resumed and no other, replicas restored, `noout` unset, the marker deleted last.
  - `TestClusterStartupGoneMeanwhile`: patching the CronJob and deleting the marker answer NotFound: exit 0.
  - `TestClusterStartupNoOutLimit`: OSDs never Ready, `startup-began` older than `NOOUT_LIMIT` in the marker: `noout` unset, and CronJobs resumed before it.
  - `TestClusterStartupKeepsItsClock`: `startup-began` present: not rewritten.
