# Power Cut (Step 11c) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Act on the spike's findings: prune orphaned Velero snapshots, add `lab secrets force-unlock` and a release that
retries, and a fixed `TestNodePowerCut`.

**Architecture:**
- **Snapshots:** `system/velero/files/prune.sh` gains a pass over the VolumeSnapshots labelled `velero.io/backup-name`.
- **Lock:** `cli/internal/rotate/lock.go` gains `ForceUnlock` and a retrying release; `cli/internal/cli/secrets.go`
  wires `lab secrets force-unlock`.
- **Test:** `test/node_restart_test.go` gains `TestNodePowerCut`, which shares `TestNodeRestart`'s helpers and adds
  "really back" checks.

**Tech Stack:** POSIX sh, Go (client-go, cobra), the test module's terratest helpers.

**Spec:** `docs/superpowers/specs/2026-10-25-power-cut-design.md` (Findings and Decisions)

## Global Constraints

- No secret value in arguments, logs or test output (markers are test strings, never secrets).
- Latest stable versions, pinned (no new dependency is expected).
- `make dev` only from `/home/nixos/homelab`; `scripts/ci-check all` before each commit; commits end with the
  session's attribution lines.
- The fixed test measures recovery as the spec says: the node Ready after the cut, no pod Unknown or not ready, and
  the apps answering through the Gateway, within 20 minutes.

## Review Focus

1. **A VolumeSnapshot of a backup still running** must never be pruned. Only snapshots whose backup no longer exists
   are deleted. Test: `TestVeleroPruneOrphanSnapshots` keeps a snapshot whose backup is InProgress.
2. **force-unlock with a stale holder** (the run that died was replaced by a live one) must refuse. Test:
   `TestForceUnlockRefusesAnotherHolder`.
3. **A release that keeps failing** (the API server down for minutes) must not hang the command. It gives up after its
   retries, and the Lease expires as before. Test: `TestLockReleaseRetriesThenGivesUp`.
4. **The pre-cut pod states the API server reports** must not count as recovered. Test: `TestPowerCutRecovered`
   (offline) rejects pods whose start is before the cut.

### Task 2: `lab secrets force-unlock` and a release that retries

**Files:**
- Modify: `cli/internal/rotate/lock.go`, `cli/internal/rotate/rotate_test.go`, `cli/internal/cli/secrets.go`,
  `cli/internal/cli/secrets_test.go`

**Interfaces:**
- Produces:
  - `func (l *LeaseLocker) ForceUnlock(ctx context.Context, name, holder string) (Lease, error)`. It deletes Lease
    `rotate-<name>` only if its holder equals `holder` (a ResourceVersion precondition), and returns what it removed:
    `type Lease struct{ Holder string; Acquired, Renewed time.Time }`.
  - `lab secrets force-unlock <name> <holder> [--yes] [--env]`: prints the holder and times, asks (`confirm`), and
    calls `ForceUnlock`.
  - The release retries its Get/Delete with backoff for up to two minutes (`LeaseLocker.ReleaseFor`, default
    `2*time.Minute`), then gives up silently, as now.

- [ ] **Step 1: Write the failing tests.**
  - `TestForceUnlock`: a held Lease is removed and the returned holder matches.
  - `TestForceUnlockRefusesAnotherHolder`: the error names the actual holder, and the Lease stays.
  - `TestLockReleaseRetries`: the first two deletes fail (reactor), the third succeeds, and the Lease is gone.
  - `TestLockReleaseRetriesThenGivesUp`: with `ReleaseFor: 50ms`, release returns.
  - `TestSecretsForceUnlockAsksFirst`, in cli: without `--yes` and without a terminal it errors and the Lease stays.
- [ ] **Step 2: Run the tests.** `go test ./internal/rotate/ ./internal/cli/` fails.
- [ ] **Step 3: Implement.** Make the "being rotated by" error also say `or lab secrets force-unlock <name> <holder>`.
- [ ] **Step 4: Run the checks.** `make -C cli test check` passes.
- [ ] **Step 5: Commit.** `feat(lab): lab secrets force-unlock, and a lock release that retries while the API server
  comes back`
