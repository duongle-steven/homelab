# Step 10f: Argo Workflows and Argo Events replace Woodpecker — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Forgejo org `ci`'s repositories build, sign and attest their images through Argo Events and Argo Workflows' golden path; Woodpecker is gone.

**Architecture:** Three wrapper charts: `platform/argo-workflows` (controller and SSO server), `platform/argo-events` (controller), `platform/ci` (EventBus, Forgejo EventSource and Sensor, the `WorkflowTemplate`s, secrets, seccomp policies). `lab infra forgejo sync` keeps org `ci`'s webhook and bot user; OpenBao signs through transit; Kyverno audits the signatures.

**Tech Stack:** Helm wrapper charts synced by Argo CD, argo-workflows 2.0.18 (v4.1.6), argo-events 2.4.28 (v1.9.11), Buildah, cosign (`hashivault://`), Syft or Trivy for SPDX, OpenBao transit, Kyverno, Go (`cli/`, `test/`).

**Spec:** `docs/superpowers/specs/2026-11-13-argo-ci-design.md`

## Global Constraints

- Latest stable releases, pinned exactly; every image by tag or digest (Kyverno's pinned-images policy).
- Hosts as `<host>.{{ .Values.global.baseDomain }}`; no domain or IP in a chart (`scripts/check-env-config`).
- Every workload: RuntimeDefault seccomp, no privilege escalation, non-root where the image allows, or a `PolicyException` with `homelab/reason`.
- Every meshed namespace has an `allow`; webhooks' pods carry `istio.io/dataplane-mode: none`; `scripts/check-mesh-policies` passes.
- Every PVC carries `homelab/backup` (`scripts/check-backup-groups`); every secret has a catalog entry (`lab secrets check`).
- Secrets via ExternalSecrets from SecretStore `openbao`, keys under the reading namespace; generated ones under `<namespace>/generated/`.
- New components get `test/scopes.yaml` entries in the same change.
- `just dev` only from `/home/nixos/homelab` (never this worktree); never beside the testbed.
- Commits end with the Co-Authored-By and Claude-Session lines.

## Review Focus

1. A Forgejo push whose payload lacks fields the Sensor reads (a tag push, a branch deletion with an all-zero `after`): no Workflow, or one that ends `error` with a status, never a crash loop of the Sensor.
2. A `.ci.yaml` that is not YAML or names `image` with a path outside the repository's name (`../other`): the run fails with a `failure` status, nothing pushed.
3. The signing step on a pull request or a non-default branch: never signs (only default-branch pushes reach zot).
4. A Workflow submitted through the UI by an editor with an inline template: refused by `templateReferencing: Strict`.
5. Two pushes in a row to the same repository: both run; the second's status lands on its own commit.

Task 4 pins 1–3 and 5 in its offline template tests where a render can show them and in the `CI` e2e spec otherwise; Task 1 pins 4 (render) and Task 8 (e2e).
